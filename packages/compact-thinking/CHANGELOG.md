# Changelog

## [Unreleased]

## [0.7.0] - 2026-10-30

### Added

- ThoughtMember / Transparent layout classification for tool-display's verb-group ([#157](https://github.com/TwIStOy/pi-extensions/issues/157)): on every content rebuild a finished, collapsed, text-free assistant block marks itself as an eligible ThoughtMember (`setThoughtMember` from `@htwang-contrib/common`), and a streaming or user-expanded text-free thinking block marks itself Transparent. The block keeps building its normal heading row either way; only when tool-display's verb-group claims an eligible member (`setThoughtMemberClaimed`) does the patched render return zero lines, so a standalone finished thinking block keeps its `◆ Thought for Xs — summary` row while one folded between tool-call batches disappears without breaking the group. Claims are cleared on every content rebuild, so a stale fold never survives a message change, and expanding a run during streaming keeps the block visible (Transparent) after the run finishes.
- New `Blank Lines Around Thinking` config item (`blockSpacing`, default 0, range 0-5; hand-edited values are clamped on read and re-read on every render so `/config` edits apply live): the number of blank lines emitted before and after each thinking block. 0 joins thinking rail lines directly into the tool rail column; boundaries against visible assistant text and any non-rail sibling above (user messages, session notices) always keep at least one blank line regardless of the setting.
- The thinking gutter bar now plays a per-row brightness wave while a thinking run is active, modeled on grok-build's accent rail: each row's color is a `sin²(tick·speed + row/32·2π)` lerp between `borderMuted` (trough, so the bar never disappears) and a peak role resolved through `text` → `muted` → `thinkingText` (so themes that leave `text` empty — terminal default fg, e.g. catppuccin-mocha — still animate), with a ~1.4s period regardless of the configured animation interval. The spatial wavelength is fixed at 32 rows like grok-build, so adjacent rows differ by at most `amplitude·sin(π/16)` ≈ 19.5% of the color range; the amplitude itself scales with the widget's row count (`min(1, rows/13)`) so short blocks stay subtle and tall blocks reach the full peak. Finished runs keep the static `borderMuted` bar, and themes without color accessors fall back to the static bar.
- Compact thinking blocks are now click-expandable per block. Each rendered thinking run is wrapped in a `MouseRegion`; a left click toggles that single run between the compact preview (or summary) and the full raw thinking text, leaving other runs untouched. The collapsed truncation hint now reads `... (N more lines, click or ctrl+t to expand)` and the expanded view ends with `... (click to collapse)`; expanding a summarized run shows the original thinking, not the summary. Per-run expansion state resets when the global thinking visibility is toggled (ctrl+t), matching the stock component's override reset.

### Fixed

- Thinking inside an expanded tool group now uses the group's indented subrow layout for its heading and body, including streaming previews and clicked-open text. Collapsing the group restores standalone layout for thinking that remains visible.
- Thinking-led messages no longer crash pi with `Maximum call stack size exceeded` when the previous chat sibling is a tool-display widget (or any other component whose `render` probes this one via `componentRendersLines`). The leading-blank walk treats `ToolExecutionComponent` as a rail sibling by identity and never calls its `render`, so it cannot ping-pong with tool grouping; the shared probe also refuses to re-enter a render already in progress.
- Active thinking runs collapsed to a single heading line while streaming; they now render the heading plus the last `Preview Lines` (`previewLines`, default 3) thinking lines again, oldest first, with the wave running down the block's actual height — the single-line layout is kept for finished runs only. The 5-row wave-amplitude floor is retired with the single-line active block. ([#153](https://github.com/TwIStOy/pi-extensions/issues/153))
- The animation tick no longer rebuilds streaming thinking components every frame. Each `updateContent` constructs a fresh `StrictThinkingPreview` with a cold wrap cache, so rebuilding at 45ms re-wrapped the entire (growing) thinking text twice as often as before and starved delta rendering — thinking text visibly arrived in bursts. The gutter wave now reads the animation frame lazily at render time (`createWaveBar` takes a `() => number`), so a plain `requestRender()` animates it; full `updateContent` rebuilds (needed for the heading highlight and duration) only run every other tick, restoring the previous 90ms cadence.

### Changed

- The active thinking rail glyph is now `┃` (was `▌`), matching the run rail used by expanded thinking runs and tool calls; the wave's colors, period, wavelength, and amplitude scaling are unchanged, as is the static `borderMuted` fallback bar for themes without color accessors. ([#155](https://github.com/TwIStOy/pi-extensions/issues/155))
- Thinking blocks no longer add fixed blank lines around themselves. The assistant message's leading blank and the per-run before/after spacers are replaced by a single spacing walk driven by `blockSpacing`: thinking-led messages open with `blockSpacing` blank lines (text-led messages keep the stock leading blank), run↔text gaps floor at `max(blockSpacing, 1)`, and run↔run plus trailing-run gaps use `blockSpacing` exactly — previously consecutive runs split by a tool call stacked two spacers between them, and every thinking-led message opened with an unconditional blank line. A thinking-led message at `blockSpacing = 0` restores its leading blank at render time unless the closest previous visible chat sibling renders into the rail column (a tool execution or a rail-tail-marked message), found by walking the TUI tree via `findComponentContext` from `@htwang-contrib/common` — the sibling is only knowable at render time because `updateContent` also runs before the component is attached to the chat container, and joining is what keeps the rail column continuous across tool boundaries. When the message's last visible content is a thinking run, the component marks itself with the shared rail-tail spacing (`setRailTailSpacing` from `@htwang-contrib/common`) so tool widgets below drop their own leading blank and the configured gap fully owns the rail→tool boundary. Error/abort/length notices still append with their own leading blank line and clear the marker, as does rendering with thinking visible (ctrl+t).
- The default `animationIntervalMs` is now 45 (was 90), closer to grok-build's 33ms/0.15rad-per-tick cadence — the 90ms tick made the wave visibly steppy. The heading highlight animation shares the tick and is correspondingly smoother.
- Dev dependencies bumped to `@earendil-works/pi-tui`, `@earendil-works/pi-coding-agent`, and `@earendil-works/pi-ai` `^0.85.0` (`MouseRegion` and mouse dispatch landed in pi-tui 0.84.2+; the stock `Markdown.paddingX` became private in 0.85.1, so the expanded-thinking indent now sets it through the internals cast). npm hoisted `pi-coding-agent` 0.85.1 to the root `node_modules` for all workspaces as a side effect.
- Completed thinking runs now render as a single rail line: `◆ Thought for Xs — <summary>` when a summary exists, `◆ Thought for Xs` when it does not, and `◆ Thought for Xs [ Summarizing... ]` while the side call is pending. The bullet sits in the shared rail's bullet column (5) with the rail column empty (`mark: none`) and the body at column 7, so thinking lines align with tool-call lines rendered through `@htwang-contrib/common`'s `TOOL_RAIL_LAYOUT`. Over-wide summaries truncate with an ellipsis instead of wrapping. Restored duration/summary session entries render through the same single-line path. ([#147](https://github.com/TwIStOy/pi-extensions/issues/147))
- The `▌` gutter and the `Gutter` component are retired. Thinking runs now compose through the shared rail (`ToolRailComponent`/`renderRailLines`): the active run's wave animation moved into the rail column via `RailSpec.bar` (same `createWaveBar` colors and wavelength), and because collapsed runs are single lines now, the row count handed to the wave is floored at 5 rows — the height of the former collapsed block — so the wave keeps its former amplitude instead of dimming to `min(1, rows/13) ≈ 8%`. Expanded runs render the preview under a dim `┃` run rail on every row. `StrictThinkingPreview` is expanded-only (full text plus `... (click to collapse)`); collapsed runs no longer show `previewLines` preview rows or the separate `✦ Summary:` line, so the `Preview Lines` config item no longer affects rendering. The expanded-thinking (thinking toggled visible) markdown indent now uses `TOOL_RAIL_LAYOUT.prefixWidth`. ([#147](https://github.com/TwIStOy/pi-extensions/issues/147))
- The animation tick still only `requestRender()`s the wave, but the every-other-tick `updateContent` rebuild now skips components that have an expanded run: rebuilding would recreate the expanded preview's wrap cache and re-wrap the full thinking text every 90ms. Delta-driven rebuilds are unaffected. ([#147](https://github.com/TwIStOy/pi-extensions/issues/147))

## [0.5.0] - 2026-08-12

### Added

- Optional thinking summaries: when enabled (`Summary Enabled` config item), each finished thinking run is sent to a configurable side model (`Summary Model`, empty = session model) for a one-line summary via `executeSideCall`. The summary replaces the raw thinking preview in the compact block once it arrives; expanding thinking still shows the original content. Summaries are persisted as session entries and restored on session load, mirroring the duration entries.
- Summary display is prefixed with `✦ Summary:` so summarized blocks are clearly distinguishable from raw thinking previews, and only runs longer than `Summary Min Chars` (default 2000) are summarized.
- While a summary side-call is in flight, the finished thinking block's heading shows an animated `[ Summarizing... ]` indicator (e.g. `Thought for 9s [ Summarizing... ]`); the animation timer now stays alive until all pending summaries settle.

### Fixed

- The thinking animation `setInterval` no longer starts in non-TUI modes (print/json), where it previously spun headlessly for the whole session doing no-op work. Component refresh and the render loop are now gated on the session being a TUI session; duration entry recording still runs in all modes.
- `StrictThinkingPreview.render` re-wrapped the entire thinking text via a fresh `Text` component on every frame for every assistant message, dominating transcript frame time (~5-30ms per message per frame, ~90% of total render cost in a measured session). The rendered lines are now memoized per width and dropped on `invalidate`.

### Changed

- The compact thinking block now leaves a blank line between the heading (`Thought for Xs`) and the preview/summary lines below it; the gutter bar stays continuous across the blank line.
- The "... (N more lines, key to expand)" truncation hint now renders on the same line as the heading (e.g. `Thought for 8s ... (7 more lines, ctrl+t to expand)`) instead of taking its own line.

### Added

- The compact thinking block now renders a `▌` gutter bar (theme color `borderMuted`) in the 2-column indent, spanning the heading and preview lines.
- The expanded thinking block (thinking toggled visible) is now indented by 2 columns as well, matching the compact block's indentation. Implemented by bumping `paddingX` on the stock thinking `Markdown` children after delegating to the original renderer, so stock markdown transforms and streaming behavior are preserved.
- The compact thinking block (heading and preview lines) is now indented by 2 columns relative to regular assistant text, visually separating it from surrounding content.
- Initial release. Ported from [pi-compact-thinking](https://github.com/nostalfinals/pi-compact-thinking) with OpenAI Responses summary-title support removed. Configuration uses the shared ConfigItem mechanism (`/config`, persisted to `~/.config/pi/extensions.json`) instead of a standalone JSON file.
