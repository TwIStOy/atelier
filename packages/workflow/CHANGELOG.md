# Changelog

## [Unreleased]

### Added

- New `workflow` extension: a `workflow` tool that runs model-generated JavaScript orchestration scripts. The script's first statement must be `export const meta = { name, description }` (extracted by acorn AST literal evaluation, never executed); the body runs in a `node:vm` sandbox with injected `agent()` / `parallel()` / `pipeline()` / `phase()` / `args` / `console` globals and no host access (imports, `require`, `process`, `globalThis`, `eval`, `Function` are rejected at parse time). `agent()` calls are executed by the shared `runChildAgent` runner from `@htwang-contrib/common` — persona support via `agent_type`, per-call `model`/`thinking`/`isolated`/`max_turns`, real token-usage accounting, `~/.agent/workflow/session` child sessions, and by-parent link records so workflow children show up in `/view-subagents`. An optional JSON Schema `schema` turns the child into a structured-output producer (`terminate: true` `structured_output` tool) whose parsed value is returned to the script. Failed agents resolve to `null` without aborting the workflow. Live progress renders as a theme-colored `aboveEditor` widget in the TUI (event-driven with a 100ms throttle plus a 1s elapsed-time tick, auto-cleared after completion) or as streaming `onUpdate` partials without a UI; Esc aborts the workflow and all in-flight children. `maxConcurrency` (default 4) and `maxAgents` (default 32) are configurable via `/config`.
- `./script` package subpath export (`@htwang-contrib/workflow/script`) exposing the acorn script parser standalone, so `@htwang-contrib/tool-display` can resolve a call's `meta.name` for its `workflow` tool-row adapter without loading the full extension.
