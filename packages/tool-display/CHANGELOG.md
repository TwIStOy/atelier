# Changelog

## [Unreleased]

## [0.7.0] - 2026-10-30

### Added

- `codemode` tool display adapter: pi's built-in codemode tool (raw JavaScript source run in a QuickJS sandbox with nested tool calls) now renders in the repo's tool style instead of pi's own renderer. The header shows `Codemode <first script line>` (the `// @options:` line is skipped) with a `· N/M calls` settled/total counter once nested calls exist. While running, the collapsed body lists the nested call rows (`✓`/`✗`/`⊘`/spinner glyph, duration, cost) live from `details.calls`, rendering each nested call through its own tool's registered display adapter header when the args preview parses (`Read a.ts`, `Glob "src/**/*.ts"`, progressive verb while the nested call is running) and falling back to the raw name + args preview otherwise; once settled it keeps the last 8 call rows (with an "earlier calls" expand hint), sums model-call costs into a `Model calls: $X` line, strips the `Script completed|failed / Wall time / Output:` header from the text output but leaves the body to the expanded view — surfacing only a failed script's `Script error:` section as an error-colored excerpt. The expanded view renders the full script with JS syntax highlighting and line numbers, followed by `── calls ──` (all calls, error text included) and `── output ──` / `── error ──` sections. `renderToolCall` now routes collapsed codemode calls through the adapter even without text output (so the live call rows show while streaming) and bypasses the squashed one-line `└ <reason>` error branch for codemode, whose failure text is the whole script output. Nested-call adapter lookup goes through the new `activeRegistryRef` export in `tool-call-display.ts`, set once by `registry.ts`, so `adapters/codemode.ts` resolves sibling adapters without an import cycle.
- Added the `bashAssessment` setting (default `true`), exposed as **Bash Assessments** in `/config`. Disabling it skips new System One requests and hides both destructive and exfiltration scores, including cached results, without changing Bash execution or output.
- Bash tool calls receive asynchronous System One `destructive` and `exfiltration` probability annotations, displayed after the header's output-line count. Scores are associated with tool-call IDs and only affect display; failures, cancellation, and configuration errors never gate execution. Registers the shared System One configuration section and cancels pending assessments on turn cancellation or session shutdown.
- New `applyPatchStyle` ConfigItem (surfaced in `/config` under Tool Display) controls how `apply_patch` renders when collapsed. `"single-line"` (default) puts patch stats, progress, and failure counts inline on the header when they fit; `"two-line"` keeps the separate `└ patch …` row. Expanded per-file diffs are unchanged.
- New `writeStyle` ConfigItem (surfaced in `/config` under Tool Display) controls how the `write` tool renders when collapsed. `"single-line"` (default) appends the line-count stat inline to the header (`Write src/foo.ts +12`, success-colored, dropped entirely when the header fills the width), mirroring `editStyle`; `"two-line"` keeps the legacy header + `└ N lines` body row (with `└ empty file` for empty writes).
- New `memoryStyle` ConfigItem (surfaced in `/config` under Tool Display) controls how the ten memory tools (`memory-create` / `memory-read` / `memory-update` / `memory-delete` / `memory-search` / `memory-list` / `memory-alias` / `memory-triggers` / `memory-history` / `memory-domains`) render when collapsed. `"single-line"` (default) appends the result summary inline to the header (e.g. `Memory read core://agent · 12 lines …`, `Memory update core://agent +3 -1 · p4`), dropped entirely when the header fills the width, mirroring `editStyle` / `readStyle`; `"two-line"` keeps the legacy header + `└ …` body row.
- pi-mcp-adapter tool calls are now rendered through tool-display's generic pattern instead of the adapter's own `renderCall`/`renderResult` components. Tools owned by pi-mcp-adapter (the `mcp` proxy, direct `<server>_<tool>` tools, namespace proxies) are detected via `pi.getAllTools()` `sourceInfo.path` (refreshed on `session_start`, `before_agent_start`, and the adapter's `pi-mcp-adapter/status/v1` event, with an `MCP`-label fallback at render time), then routed through `renderToolCall`: generic bold header named from the tool label (`MCP: take_screenshot` → `McpTakeScreenshot`), collapsed `└ N lines` footer, the full generic expanded view, and the shared `≠ <reason>` error branch. Click-to-expand and the hover affordance work as with other owned tools. A new `mcpToolCalls` boolean ConfigItem (default true) restores the adapter's own renderers when disabled.
- Built-in MCP tools (`mcp__<server>__<tool>`, from pi's `builtin:mcp` extension) render through the same generic pattern as pi-mcp-adapter tools: detection is by tool-name pattern (the same regex pi's own renderer resolver uses), so it also covers resumed sessions whose server has not connected yet. The header display name camelizes the full tool name (`mcp__radius__search` → `McpRadiusSearch`), errors flow through the shared `≠ <reason>` branch, and the `mcpToolCalls` setting gates the behavior the same way.
- New `editStyle` and `readStyle` ConfigItems (surfaced in `/config` under Tool Display) control how the `edit` and `read` tools render when collapsed. `editStyle` accepts `"single-line"` (default; the post-#154 inline diff-stats header) or `"two-line"` (legacy header + `└ diff +N -M unified|side-by-side [change bar]` body row). `readStyle` accepts `"two-line"` (default; legacy header + `└ N lines` body row) or `"single-line"` (the `· N lines` line-count is appended inline to the header after the path and any `:offset-limit` range suffix, dropped entirely when the header fills the width, mirroring the bash adapter).
- Three-layer layout folding for tool calls, replacing the #145 single read-only aggregate rule ([#157](https://github.com/TwIStOy/pi-extensions/issues/157)). **Verb-group** folds consecutive collapsed tools whose name has an Aggregate Rule (built in: `grep` / `glob` / `ls` / `read`; extensions register more via `@htwang-contrib/common`'s `registerAggregateRule` or the `tool-display:register-aggregate-rule` event) into one `  ❙  ◈ Read N files, …` header row. The verb-group requires at least two members: a lone collapsed `read` keeps its ordinary path-bearing `◆ Read <path>` line, since a one-member aggregate would only hide the path behind `◈ Read 1 file`. **ThoughtMember**: a finished, collapsed, text-free assistant block (marked by compact-thinking) folds into the surrounding verb-group at height 0 without appearing in the header; streaming or user-expanded thinking stays visible as a Transparent sibling that neither joins nor breaks the group, and a user-expanded tool keeps its own rows while the rest of the group stays claimed. **Truncation**: dense runs of collapsed tools the verb-group did not claim hide their oldest entries behind a header once the participant count exceeds `groupMaxVisible + 1` (uniform runs phrase as `Ran N commands` for bash or `Edited N files` for edit/write/apply_patch; mixed runs fall back to `N more`; with the verb-group off, rule-registered names keep their Aggregate Rule phrasing). Both headers render red with a `· N failed` suffix when any covered member errored, and grouping is recomputed from the chat sibling list on every render so leader election stays idempotent across streaming appends and session replay.
- New config items: `groupToolVerbs` (boolean, default true) switches the verb-group layer off so rule-registered tools render as ordinary collapsed rows and are only folded by truncation; `groupMaxVisible` (number, default 10, 0 disables truncation) bounds how many entries of a dense run stay visible.
- The verb-group header row is clickable and expands into a grok-style subrow list ([#146](https://github.com/TwIStOy/pi-extensions/issues/146), ported onto the verb-group leader during the #157 rebase; truncation headers still ignore clicks). Clicking the `◈` summary row toggles the whole group: the summary keeps its counts but switches the rail to the continuation `┃`, and every member (the leader included) renders one indented subrow `  ┃     ◆ <summary>` built from its adapter's `formatCallHeader` collapsed to a single line (ANSI-aware `truncateToWidth` safety net). Subrow rail and bullet take the member's own status — green, red, or spinner while streaming — and hover swaps the `◆` for the `›` affordance. Clicking a subrow expands that one call through the existing expanded-render path while its siblings stay subrows; clicking it again folds it back. Clicking the summary row again collapses the group to the single aggregate line and resets any individually expanded members. Group expansion state lives in a `WeakMap` keyed by the leader component, so replaced instances (streaming/replay) and destroyed leaders reclaim their state automatically, and members that join an expanded group mid-stream appear as subrows on the next frame. Expanded widgets outside an expanded group still break candidate runs, non-aggregate tools keep the stock click-to-expand behavior, and clicks on the blank separator line above the summary are ignored.
- Collapsed tool widgets now show a hover affordance in fullscreen mode: hovering a finished, collapsed tool call replaces the leading `◆` status diamond with `›` (color preserved), signaling click-to-expand; expanded widgets always keep `◆`. Hover is tracked by the patched `ToolExecutionComponent.handleMouse` on `move` events (a module-level singleton so only one widget is hovered at a time), and cleared by `Container`/`Editor` prototype patches that claim otherwise-unhandled `move`/`wheel` events when a tool was hovered — covering the cursor moving onto transcript text, blank areas, or the editor. Requires all-motion mouse tracking, so it is inactive under tmux/Zellij/GNU Screen where pi only enables button-motion tracking.
- `apply_patch` tool display adapter: the Codex-style patch tool (registered by `@htwang-contrib/apply-patch` for OpenAI GPT models) now renders in the repo's Edit/Write style. The header shows `ApplyPatch <path>` (accent, `+N more` for multi-file patches); the collapsed line is `└ patch [i/n] +N -M unified|side-by-side · F files [change bar]` with a `✗ N failed` marker on failed hunks (header icon also turns red); the expanded view renders per-file unified diffs through the same `delta` pipeline as Edit, with `├`/`└` per-file headers for multi-file patches and a `✗` failure list. Falls back to parsing the raw patch text for counts while the call is still streaming. The delta rendering helpers (`renderWithDelta`, `renderChangeBar`, `resolveIsSplit`) moved from `edit.ts` to `adapters/shared.ts`, and `generateUnifiedDiff` now comes from `@htwang-contrib/common`.

### Changed

- The elapsed-time timer on a tool call's first body line is now hidden unless the call ran for at least 60 seconds (`TIMER_MIN_ELAPSED_MS` in `format.ts`). Short calls render with no timer prefix, and the header reclaims the timer's body-line width.
- The `read` / `write` / `edit` / `bash` headers now reflect the call's state: while running they use the progressive verb (`Reading src/foo.ts`, `Writing src/foo.ts`, `Editing src/foo.ts`, `Running <command>`) and switch to the past tense once settled (`Read`, `Wrote`, `Edited`, `Ran`), matching the aggregate phrasing (`Read 2 files`, `Edited N files`, `Ran N commands`). The bash header's wrap budgets account for the changing verb width. Applies to collapsed headers, expanded headers, and verb-group subrows alike.
- The chat-sibling scanning helpers (`findSiblingContext`, `siblingRendersLines`) moved to `@htwang-contrib/common` as `findComponentContext` / `componentRendersLines` and are imported from there; grouping and spacing behavior is unchanged.
- Tool groups no longer force a leading blank line below a thinking rail tail. When the previous visible chat sibling carries the shared rail-tail spacing marker (set by compact-thinking when the assistant message ends with a thinking run), `applyGroupSpacing` strips the tool's own leading blank instead of ensuring one, so the marker's configured gap fully owns the thinking→tool boundary and the rail column renders continuously at `blockSpacing = 0`. Unmarked siblings (assistant text, user messages, session notices) still get the guaranteed leading blank.
- All tool call lines (header, collapsed content, expanded content) now render through the shared rail column renderer from `@htwang-contrib/common` (`renderRailLines`, landed for #143): rail glyph at column 2, status bullet at column 5, body at column 7. Every call draws a `┃` rail on each row (single-line blocks included), with the bullet only on the first. The rail and bullet take the status color (green success, red error, plain while spinning); the hover affordance swaps the `◆` bullet for `›` as before ([#144](https://github.com/TwIStOy/pi-extensions/issues/144)).
- The `│   ` header continuation prefix and the four-space `INDENT` content indent are retired; continuation and content lines are now rail body rows aligned under the first body column. `Subagent`/`workflow` task rows dropped their `├`/`└` tree branches and render as plain rail continuation rows; the same applies to memory/journal expanded content, which no longer draws its own `│ ` bars ([#144](https://github.com/TwIStOy/pi-extensions/issues/144)).
- `ToolDisplayAdapter` width parameters (`formatCallHeader` / `formatCollapsedContent` / `formatExpandedContent`) and the `ContentRenderer` callbacks now receive the rail body width (`toolRailBodyWidth(width)`: terminal width minus 7) instead of the full terminal width; adapters self-truncate against that budget and `renderRailLines` still applies a final ANSI-aware truncation, so terminals at or below the prefix width no longer produce "exceeds terminal width" lines. The elapsed-time timer now consumes the first body line's budget instead of the old icon prefix ([#144](https://github.com/TwIStOy/pi-extensions/issues/144)).
- `bash` tool calls now render as a header-only widget when collapsed: the `└ N lines` footer line is gone. Instead, when the header has room, a dim `· N lines` output-line count is appended to the end of the header (after the command or `in <cwd>` suffix; dropped entirely when the header already fills the width). `ToolDisplayAdapter.formatCallHeader` gained an optional trailing `output` parameter that `renderToolCall` now passes through, so adapters can surface output-derived info in the header.
- Todo tool calls now render as a header-only widget with no collapsed output line: the collapsed body (`└ Updated #5`-style echoes of the tool result) carried no information beyond the header. The old single `todo` adapter was replaced by per-tool adapters for the split todo tools (`todo_create` / `todo_update` / `todo_list` / `todo_get` / `todo_delete` / `todo_clear`), each rendering its own header (e.g. `TodoUpdate [completed] #5 <subject>`) via a shared `createTodoAdapter(toolName)` factory; the legacy `todoAdapter` export was removed.
- Collapsed tool summaries now sit flush left, aligned under the status icon. The generic collapsed summary (`└ N lines — <key> to expand`, used by tools without a display adapter such as `todo_update`) no longer prefixes a four-space indent, matching the existing read/edit/grep adapter convention.
- `ask_user_question` no longer renders a collapsed `└ N questions` line; its collapsed view is the header only. The `askUserQuestionCollapsed` adapter-gating clause in `renderToolCall` was removed together with it.
- `bash` calls with a `description` now lead with it: the header is a single-line `Bash <description> in <cwd>` (description in accent) and the command is hidden from the collapsed view, surfacing as a muted `$ <command>` block at the top of the expanded view, above the output. Calls without a description keep the previous width-wrapping `Bash <command> in <cwd>` header.
- Tool call blocks now glue into one contiguous group regardless of turn boundaries or render path. The patched `ToolExecutionComponent.render` previously omitted the blank separator line only for adapter-rendered blocks whose immediate previous chat sibling was another tool component, resolved once and cached; tools falling back to pi's stock renderer kept the stock leading `Spacer(1)`, and an invisible (zero-line) sibling between two tools broke the grouping. The previous-sibling lookup now runs on every render, skips zero-line siblings (e.g. assistant turns with no visible content), and the stock-renderer fallback path strips its leading blank line the same way, so consecutive tool widgets always render flush while a tool group still separates from non-tool content with one blank line.
- `edit` tool calls now render as a header-only widget when collapsed ([#154](https://github.com/TwIStOy/pi-extensions/issues/154)). The `└ diff +N -M unified|side-by-side [change bar]` footer line is gone; the diff stats (`+N`, `-M`, `unified|side-by-side`, change bar) move inline onto the header, appended after the path when the header has room (dropped entirely when the path fills the width). The expanded view still renders the full delta diff.
- Tool rendering is now cached end to end (`src/render-cache.ts`), so pi-tui's every-frame full-tree re-render no longer recomputes every tool block. A frame epoch (bumped by a patched `doRender` on the TUI instance captured via `setWidget`) bounds frame-scoped memos: `resolveGroupRole` runs at most once per component per frame instead of once per render call, which collapses the previous O(tools × region) sibling scans and — combined with the lines cache — turns the backward visibility probes (`findPreviousVisibleSibling`) from full sibling renders into cache-key comparisons, eliminating the O(N²) full renders in dense tool runs. The per-component lines cache keys on width, probe depth (probed renders resolve spacing differently and get a separate slot), a state version bumped from a wrapped `updateDisplay` (pi core's single mutation choke point: `updateArgs` / `updateResult` / `setExpanded` / `setShowImages` / …), hover state, the async bash annotation, a group-role summary (including member partial/error signature), previous-sibling spacing booleans, the spinner tick (only while something visible is spinning, quantizing animation to its 80 ms frame rate), the displayed timer label (self-quantizing at its own precision), theme identity, a render-env version (MCP tool-set refreshes), and common's config-file version. Settled tool blocks now render as one key comparison per frame; only rows with a live spinner or timer ever recompute. `getTextOutput` is memoized per result object (pi core replaces results wholesale in `updateResult`), and `loadConfig` calls land on common's new mtime-cached config reader instead of re-reading and re-parsing `extensions.json` per call. Grouping itself is computed once per hard-break-bounded region per frame (`memoizedRegionRoles`) and shared by every component in the region, replacing the per-component region scans, and the backward visibility probe consults a per-frame line-count registry (`recordFrameLineCount` / `frameLineCount`) — parents render children top-down, so a probed sibling has already rendered this frame and its recorded height answers the probe without re-invoking its render. Measured end to end (200 settled tool blocks, 80 columns): ~33 ms/frame before caching, ~11 ms with the per-component caches, ~1.9 ms with region sharing and the line-count registry.

### Fixed

- Expanded verb-groups now pass their subrow layout to enclosed thinking blocks, keeping their rail and indentation aligned with tool members. Thinking outside the group's member bounds retains its standalone layout.
- The verb-group summary row is clickable again when it directly follows a compact-thinking rail tail. `applyGroupSpacing` strips the leading blank below a sibling carrying the rail-tail spacing marker, but the click router still derived the summary row's y from `__tdAggregateLeadingBlank` as if the blank were present, so a click on the visible summary hit the separator-line guard and was swallowed. The flag now also accounts for the rail-tail marker, keeping click routing aligned with the rendered layout.
- Grouping and spacing no longer crash pi when a previous chat sibling (typically compact-thinking) probes this widget from inside `render`. Previous-visible lookup now goes through `componentRendersLines`, which shares the reentrancy guard, instead of calling `render` directly — the compact-thinking ↔ tool-display ping-pong previously overflowed the stack (`RangeError: Maximum call stack size exceeded`).
- Hovering a collapsed tool widget no longer flickers the status bullet between `◆` and `›` while the cursor moves across it. The patched `ToolExecutionComponent.handleMouse` used to delegate to the stock handler first; for default-shell tools that call routes through `Container.prototype.handleMouse`, which the hover-leave patch treats as an otherwise-unclaimed `move` and clears hover while the cursor is still inside the widget — re-claimed on the next move, cleared again on the one after, alternating the bullet per event. The patch now claims hover `move`s before the stock delegation. The hover-leave wrapper is also installed on the `Container` base class `ToolExecutionComponent` actually extends, since this module's `pi-tui` import can resolve to a different copy of the class than the component's.
- Adapter-rendered tool blocks are click-expandable again in fullscreen mode. pi's per-block mouse expansion wraps renderer output in `MouseRegion`s inside `ToolExecutionComponent`, but the patched `render` bypasses that tree: `edit` (the only `renderShell: "self"` tool) gates `handleMouse` on `selfRenderHeight`, which only the stock `render` updates, so clicks never toggled; default-shell tools only toggled when the stale child heights happened to cover the clicked line. The patch now also overrides `handleMouse`: unhandled left clicks on a finished adapter-rendered block toggle `setExpanded`, matching the stock `createResultRegion` semantics (nested regions and OSC 8 links still win).

### Removed

- `prefixLine` (dead helper from the retired line-prefix system) is no longer exported from `./format.ts` ([#144](https://github.com/TwIStOy/pi-extensions/issues/144)).

## [0.5.0] - 2026-08-12

### Changed

- Multi-line tool call headers now prefix continuation lines with a tree gutter `│` instead of plain indentation, visually connecting the header to the collapsed `└ N lines` footer. This covers multi-line `Bash` commands, wrapped `Todo` subjects, and wrapped generic tool args (the generic header no longer adds its own extra indent on continuation lines).
- The extension now only activates in TUI mode. All TUI-specific setup (config item registration, `ToolExecutionComponent` render patching, theme capture) is deferred to `session_start` and guarded by `ctx.mode === "tui"`, so running under `--mode rpc`/`json`/`print` no longer patches the component prototype or registers config items. The cross-extension `tool-display:register`/`tool-display:ready` event bus stays active in every mode so adapter registration keeps working.

### Added

- `workflow` tool display adapter: the `Workflow` tool row now matches the Read/Bash/Subagent styling. The header shows the workflow's `meta.name` (parsed from the script with the shared acorn parser via `@htwang-contrib/workflow/script`, falling back to the first script line) plus live `settled/total agents` stats. While the run is in flight the collapsed view renders per-agent rows (`├`/`└` branches, spinner/✓/✗/◌/– status glyphs, tool-call counts, error details) from the run snapshot in `details.workflow`; once finished it collapses to the standard truncated output preview (tail lines + "more lines" expand hint). The expanded view renders the full script with syntax-highlighted line numbers, followed by the full output summary. `tool-call-display.ts` now treats `workflow` like `subagent` for adapter gating (collapsed rows render from details even before text output exists) and derives the header status icon from `details.ok`.

### Fixed

- Errored tool calls (e.g. an `Edit`/`Write` blocked by read-tracker) now render their collapsed view as a single `└ <error message>` line, matching the style of normal collapsed returns, instead of an indented `✖`-prefixed reason plus an adapter marker. The error reason is the collapsed summary; the adapter's full output (the diff for `Edit`/`Write`) moves to the expanded view, which now appends `adapter.formatExpandedContent` after the reason. Previously the error-reason branch of `renderToolCall` was mutually exclusive with the adapter branch and indented the reason by `INDENT`, so a rejected `Edit` either lost its `└ diff` line entirely or floated the reason four spaces to the right of where the `└` marker sits.
- The patched `ToolExecutionComponent.render` now prepends the blank separator line that the stock component renders via its leading `Spacer(1)` child. The override bypassed the container's children entirely, so tool call rows were glued directly to the preceding assistant text or compact thinking block with no empty line in between. Consecutive tool calls from the same assistant message are exempt: when the previous chat sibling is another `ToolExecutionComponent`, the separator is omitted so parallel tool calls render as one glued group.
- Multi-task `Subagent` tool calls no longer crash pi on narrow terminals. The per-task and batch summary rows in the collapsed tool display now truncate the task description against the terminal width (width- and ANSI-aware via `truncateToWidth`/`visibleWidth`) and apply a safety-net truncation so no rendered row can exceed the terminal width. Previously the description was capped at a fixed 56 characters and the composed row was never bounded, producing lines wider than the terminal and triggering `Rendered line exceeds terminal width`.

## [0.2.5] - 2026-07-14

### Added

- Tool calls now show an elapsed-time label between the status icon and the tool name. Durations under 3s render as milliseconds (e.g. `123 ms`), 3s-90s as seconds with two decimals (e.g. `4.20s`), and 90s+ as `m:ss` (e.g. `1:30`). The timer ticks live while running and freezes at the final duration once the call completes.

## [0.2.0] - 2026-07-06

### Breaking Changes

- Removed the `bashCommandDisplayLength` config item from the Tool Display extension. It only controlled the floor for command *truncation*, and the Bash header now wraps the command onto continuation lines instead of truncating, so the knob no longer has any effect ([#11](https://github.com/TwIStOy/pi-extensions/issues/11)).

### Fixed

- The Bash tool header now wraps long commands onto continuation lines instead of truncating them with an ellipsis, so the full command stays visible in every state (partial, collapsed, expanded, errored). Continuation lines are aligned under the command start, and the description and `in <cwd>` suffix remain visible ([#11](https://github.com/TwIStOy/pi-extensions/issues/11)).
- Fixed the error icon being repeated on every wrapped line of a tool's error reason when the tool call failed and was expanded. The icon now appears only on the first line, with continuation lines aligned by padding ([#9](https://github.com/TwIStOy/pi-extensions/issues/9)).
- Fixed the Bash tool header truncating the command at a fixed point and dropping the `in <cwd>` suffix. The command now fills the available terminal width and is truncated cleanly so the description and working-directory suffix stay visible ([#8](https://github.com/TwIStOy/pi-extensions/issues/8)).
