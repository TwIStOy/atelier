# Changelog

## [Unreleased]

### Added

- Package scaffold (`@htwang-contrib/llm-wiki`): standard monorepo layout (`main: src/index.ts`), devDeps aligned with sibling packages. The pi extension entry (`src/index.ts`) is an intentional no-op stub; the pi binding (config items, tools, commands) lands in #76+.
- `src/core/paths.ts` (pi-free): `vaultLayout(root)` returns every file and directory path of a vault per the PLAN.md layout, plus the `VAULT_DIR_NAME` constant.
- `src/core/vault.ts` (pi-free): `resolveVaults({ cwd, personalVaultPath? })` discovers the project vault by walking up from `cwd` for `.llm-wiki/` (nearest existing wins), and resolves the personal vault to the override or `~/.llm-wiki`. `defaultPersonalVaultPath(homedir?)` for injection.
- `src/core/atomic.ts` (pi-free): lock-free fs primitives per ADR-0002 — `atomicWriteFile` (tmp+rename), `appendJsonl` (append-only JSON lines), `readJsonl` (tolerant JSON-lines reader shared by the events and review-queue readers), `contentHash` (sha256 hex), and `allocateSourcePacket` (mkdir-atomic `SRC-YYYY-MM-DD-NNN` allocation with EEXIST retry; date bucketed in UTC so the shared personal vault is stable across machines/timezones).
- `src/core/manifest.ts` (pi-free): `SourcePacketManifest` schema — origin discriminated by `sourceType` (`url` → url/title/contentType, `text` → title, `file` → originPath/originHash), plus `schemaVersion`, `id`, `packetDir`, `createdAt`, `contentHash`, `originalName`, and an `ingest` state (`status` pending/ingested/skipped). Atomic `readManifest`/`writeManifest` round-trip; `readManifestSafe` returns null for a missing/corrupt manifest (used by the Inbox scanner).
- `src/core/packet.ts` (pi-free): the Source Packet store — `captureSource()` for url/text/file. Writes `manifest.json` + `original/<name>` + `extracted.md` via the atomic primitives; idempotent dedup by scanning existing packets (file→originPath, url→url, text→contentHash), so repeated capture of the same key returns the existing packet with `created: false`. Fetches via an injected `UrlFetcher` port (keeps core pi-free) and supports cancellation through an optional `signal`; no packet dir is allocated when the fetch fails.
- `wiki_capture` pi tool (snake_case): captures a Raw Source into an immutable Source Packet. Resolves the project vault if present, else the personal vault. URL sources are fetched through the `@htwang-contrib/web-tools` provider chain (Jina/Firecrawl via the configured API keys; clear error when no fetch provider is configured). Re-capture of the same path/url/text is idempotent.
- `src/core/frontmatter.ts` (pi-free): YAML frontmatter parser (via the `yaml` package) splitting a markdown page into `{ title, type, aliases[], sources[] }` and a body; defensive against absent/invalid frontmatter.
- `src/core/wikilinks.ts` (pi-free): `extractWikilinkTargets(body)` parses `[[target]]`, `[[target|label]]`, `[[target#heading]]`, and `[[target#^block]]` (stripping fenced code blocks first), preserving order.
- `src/core/meta.ts` (pi-free): the metadata engine. `rebuildMeta(vaultRoot)` scans `raw/sources/**` + `wiki/**.md` and atomically regenerates all four derived artifacts under `meta/` — `registry.json` (pages with id/type/aliases/sources/resolved links/broken links/headings/excerpt/mtime + source summaries from manifests), `backlinks.json` (inverse wikilink graph, self-links excluded, sparse), `index.md` (human-readable, grouped by Page Type), and `log.md` (rendered from `events.jsonl`, tolerant of malformed lines). Exposes pure `buildRegistry` / `buildBacklinks` / `renderIndexMd` / `renderLogMd` for reuse.
- `src/core/guardrail.ts` (pi-free): `classifyPathOperation(toolName, input, { cwd, vaultRoots })` — blocks `write`/`edit` into any vault's `raw/**` or `meta/**`, flags `wiki/**` touches with the touched vault, passes everything else through. Path-bearing-only; resolves relative paths against `cwd` and normalizes `..` traversal.
- `wiki_rebuild_meta` pi tool (snake_case): rebuilds all derived metadata for the active vault (project if present, else personal) and returns a summary with counts.
- Guardrails + auto-rebuild wiring (`src/index.ts`): a `tool_call` interceptor blocks direct `write`/`edit` to `raw/**` and `meta/**` (pattern adapted from `permission-system`); direct edits to `wiki/**` are tracked and trigger a best-effort `rebuildMeta` at `turn_end`. All derived writes go through tmp+rename (ADR-0002 lock-free concurrency; no torn writes).
- `src/core/bootstrap.ts` (pi-free): `bootstrapVault(root, { topic?, now? })` creates the vault skeleton — `config.json`, `WIKI_SCHEMA.md` (Schema, generated from the `docs/llm-wiki/CONTEXT.md` glossary), `purpose.md` (Purpose), the five Page Type templates (`source`/`concept`/`entity`/`synthesis`/`analysis`), `inbox/`, `raw/sources/`, the `wiki/` page-type directories, and the append-only `meta/` seeds (`events.jsonl`, `review.jsonl`); then runs `rebuildMeta` to emit the derived `meta/` artifacts in canonical form. Idempotent — re-running creates only what is missing and never overwrites user-authored files; an optional `topic` is backfilled into `purpose.md` via a bounded marker.
- `scripts/bootstrap.ts`: standalone vault initializer (one-time setup, not a recurring agent mechanic, so intentionally not exposed as a pi tool or slash command). Run `node packages/llm-wiki/scripts/bootstrap.ts [parent-dir] [--topic "<text>"]` to create the vault at `<parent-dir>/.llm-wiki` (defaults to `<cwd>` for the project vault; pass `~` for the personal vault). Idempotent; an optional `topic` is backfilled into `purpose.md`.
- `src/core/page.ts` (pi-free): `ensurePage(vaultRoot, input)` — resolve-or-create a typed Wiki Page. Resolves first against the registry within the SAME Page Type by title or alias (case-insensitive, whitespace-tolerant); returns the existing page (`created: false`, with `matchedOn`) without writing. On a miss it instantiates `templates/<type>.md`, filling `type`/`title`/`aliases`/`sources` into the frontmatter (preserving type-specific keys like `kind`/`question`/`related`) and substituting the title into the body, then writes atomically under `wiki/<type>s/<slug>.md`. The slug is kebab-derived from the title (NFKD accent strip; deterministic hash fallback for non-ASCII), overridable via an optional `slug`, with `-2`/`-3` disambiguation when the path is taken by an unrelated page. Alias/source lists are trimmed and deduped.
- `wiki_ensure_page` pi tool (snake_case): resolve-or-create a typed Wiki Page (source | concept | entity | synthesis | analysis) in the active vault (project if present, else personal). Because it writes via fs and so bypasses the `write`-tool guardrail, it registers the vault for the existing turn-end `rebuildMeta` on creation so derived metadata stays current.
- `src/core/recall.ts` (pi-free): the recall engine. `searchRegistry(registry, query)` tokenizes a query and ranks pages by field-weighted matches (title×10, alias×8, heading×5, id×4, excerpt×2), reporting which fields matched. `expandByGraph(seeds, registry, backlinks)` is the four-signal Graph Relevance model — direct link×3 (forward or backward adjacency), source overlap×4 (distinct shared frontmatter `sources[]`), Adamic-Adar×1.5 (common neighbours weighted by 1/log degree), type affinity×1 — computed against the seed set minus the page itself so a keyword hit can also be flagged graph-relevant to the other seeds. `recallVault(vaultRoot, query)` builds the registry fresh (always current, no stale mid-turn cache) and merges keyword + graph hits per page; `mergeVaultResults` dedups across vaults by page id, keeping the highest-scoring instance as primary and listing every vault in `vaults[]`. Exposes a `RecallProvider` interface and `recallAcross(roots, query, { provider? })` seam: when a provider is supplied its hits are merged in (tagged `vector`); absent, behaviour is the registry + graph fallback (the v1.1 qmd vector-recall hook).
- `wiki_search` pi tool (snake_case): keyword search over ONE vault (the active vault — project if present, else personal). Returns ranked hits with score and matched fields; no graph expansion and no cross-vault merge (that is `wiki_recall`).
- `wiki_recall` pi tool (snake_case): Layered Recall — keyword search + four-signal Graph Relevance across BOTH the project vault (if present) and the personal vault, merged and deduped by page id. Each hit is annotated with the vault(s) it came from and why it matched (`keyword` | `graph`; `vector` once a recall provider is wired). Graph expansion surfaces pages the keyword search missed but that are related via wikilinks, shared sources, common neighbours, or page type.
- `src/core/review.ts` (pi-free): the Review Queue store, an append-only log over `meta/review.jsonl`. `ReviewItem` carries `id`/`filedAt`/`packetId`/`kind`/`title`/`action`/`status` plus optional `note`/`query`; actions are constrained to `create_page` | `deep_research` | `skip`, statuses to `open` | `resolved`. `appendReviewItem` auto-allocates a lock-free `REV-<UTC-compact>-<rand>` id and `filedAt` and sets `status=open`; `listReviewItems(vaultRoot, { status? })` round-trips in file order and skips malformed lines (default returns all items — backward-compatible with ingest; pass `open`/`resolved`/`all` to filter). `resolveReviewItem(vaultRoot, id, decision, { note? })` records a decision constrained to one of the three actions (rejecting any other value), marks the item `resolved` with `resolvedAt`/`resolvedAction` (and an optional `resolutionNote`, kept distinct from the filed `note`), and rewrites the file atomically (tmp+rename, ADR-0002); resolved items leave the open list. Throws on unknown id or already-resolved items.
- `src/core/ingest.ts` (pi-free): the batch ingest pipeline. `listPendingPackets(vaultRoot)` scans `raw/sources/**` for `ingest.status === "pending"`. Pure `parseAnalysis` / `parseGeneration` extract a single fenced `wiki-analysis` JSON block and one-or-more `wiki-page:<type>` blocks (plus an optional `wiki-overview` block); a missing/malformed analysis block or a generation with no `source` page is treated as a parse failure. `ingestBatch(vaultRoot, { caller, signal, now, packetId })` runs the serial two-step (analysis → generation) through an injected `SideCaller` port so the core stays pi-free: for each pending packet it builds the analysis prompt (vault Purpose + an existing-wiki digest + the packet's `extracted.md`), then the generation prompt, applies the result, files the analysis review items, sets the manifest `ingest.status = "ingested"`, and finally rebuilds metadata + appends an `ingest` event. Page application goes through `ensurePage` (dedup by title/alias): a created page is written with full cited content, while an already-existing related page is *updated* additively — the packet id is unioned into its frontmatter `sources[]` (all other keys and the body preserved) so the citation graph reflects the new source without clobbering prior content. `wiki/overview.md` is always maintained: a model-emitted overview block replaces it wholesale, and when the model omits it a per-source line (`- [[sources/SRC-…]] — <summary>`) is appended (creating the file if absent). Review filing is deduped per packet (kind+title+action) so a crash-and-retry never duplicates items. Each side-call (analysis, generation) is retried up to `maxAttempts` (default `DEFAULT_INGEST_MAX_ATTEMPTS = 3`) when the output is unparseable or the provider errors — an in-batch retry that absorbs LLM output non-determinism; the packet only fails after all attempts are exhausted. Re-entrant: a packet that fails stays `pending` and is retried on the next call; already-ingested packets are skipped.
- Injectable clock: `resolveNow(now?)` now lives in `@htwang-contrib/common` (`src/time.ts`), exposed both from the main entry and a new pi-free sub-entry `@htwang-contrib/common/time` (common's `package.json` gained an `exports` map; `"."` preserves the existing entry, `"./time"` loads only `time.ts` so it pulls in no pi). It accepts a `Date`, a `() => Date` thunk, or undefined→now. The llm-wiki pi-free core (`review`, `ingest`, `bootstrap`) imports it from the `/time` sub-entry so the core stays pi-free while sharing one source of truth repo-wide; the local `src/core/time.ts` copy was removed.
- `wiki_ingest` pi tool (snake_case): batch-ingests every pending Source Packet in the active vault into typed, cited Wiki Pages via two side-calls (analysis, then generation), each retried up to `ingestMaxAttempts` on a bad-format or provider error. Optional `packetId` restricts the run to one packet. Idempotent and re-entrant; interactive ingest is skill-guided (call `wiki_capture` / `wiki_ensure_page` directly).
- `/wiki-ingest` slash command: runs the same batch directly via side-calls (off-conversation, no conversation pollution) and notifies the summary. Optional argument is a packet id.
- Ingest ConfigItems (surfaced via `/config`): `ingestModel` (select) — the model used for batch `wiki_ingest` side-calls, defaulting to empty = follow the session's current model (options cached at `session_start` from the model registry); `ingestMaxAttempts` (number, default 3, 1–10) — max attempts for each side-call when the output is unparseable or the provider errors (1 = no retry).
- `wiki_review` pi tool (snake_case): lists and resolves Review Queue items for the active vault (project if present, else personal). `action=list` returns open items by default (optional `status` of `open`/`resolved`/`all`); `action=resolve` records a decision (`create_page` / `deep_research` / `skip`) plus an optional note. Per #82, resolving only records the decision and removes the item from the open queue — the actual page creation / web research is performed in-session by the agent (guided later by the bundled skill, #84).
- `/wiki-review` slash command: walks open Review Queue items one by one for the active vault via an interactive `select` loop (`Create page` / `Deep research` / `Skip` / `Stop`), prompting for an optional note on `create_page`/`deep_research`, and recording each decision through the core store. Falls back to a summary `notify` (plus a hint to run in an interactive terminal) when no dialog-capable UI is available; reports "no open items" when the queue is empty.
- `src/core/inbox.ts` (pi-free): `scanInbox(vaultRoot)` lists the vault's Inbox drop zone against file-type Source Packet manifests — top-level `.md`/`.markdown`/`.txt`/`.text` files only. A file with no matching `originPath` is `uncaptured`; one whose `originHash` differs from the current content is `modified`; an unchanged match is `captured`. URL/text packets are ignored for matching. Returns empty lists when the Inbox dir is absent.
- `src/core/lint.ts` (pi-free): the Lint engine. `lintVault(vaultRoot)` builds a fresh registry + backlinks + Inbox scan and emits one finding per issue — orphan pages (no incoming wikilinks; `overview` exempt; skipped when the wiki has ≤1 page), broken wikilinks (unresolved targets), duplicate aliases (a title/alias claimed by >1 page), coverage gaps (pages citing unknown Source Packets = error; `ingested` packets cited by no page = warning), and Inbox drift (uncaptured/modified files). Findings are deterministically ordered; `summary` carries error/warning totals and per-kind counts. `renderLintReportMd`/`writeLintReport` emit `meta/lint-report.md`; `applyLintFixes` auto-captures uncaptured Inbox files (the only safe, deterministic repair — modified files stay report-only since capture dedups by path).
- `wiki_lint` pi tool (snake_case): runs the Lint engine on the active vault, writes `meta/lint-report.md`, and returns a summary; `fix: true` auto-captures uncaptured Inbox files.
- `src/core/status.ts` (pi-free): `wikiStatus(vaultRoot)` — page/source counts, pages-by-Page-Type, pending ingests (manifests with `ingest.status === "pending"`), unresolved Review Queue items (reuses `review.ts`'s `listReviewItems` with `status=open`), Inbox drift counts, and the last N `events.jsonl` entries (most-recent-first). `renderStatusSummary` for the tool output; `renderSessionStartNotice` for the one-line hint (non-zero pending segments only, else `nothing pending`).
- `wiki_status` pi tool (snake_case): reports the active vault's status (counts, by-type, pending ingest/review, Inbox drift, recent events).
- `/wiki-lint` and `/wiki-status` slash commands: thin command surfaces over the same core engines (`/wiki-lint` accepts `--fix`).
- `src/config.ts` + `sessionStartNotice` ConfigItem (`/config` → LLM Wiki): toggles the session-start hint. The `session_start` handler resolves the active vault on disk, computes status, and `ui.notify`s the one-line hint; silent when disabled, when no vault exists, or on error (never breaks the session).
- `readEvents` is now exported from `src/core/meta.ts` so status (and future consumers) can read `meta/events.jsonl`.
