# User Message

Submitted prompts use a thinking-level-colored gutter and italic Markdown. When System One is configured, a muted complexity assessment appears below each new prompt; see [System One](../common/SYSTEMONE.md).

In Pi's fullscreen mode, the prompt for the turn being read stays at the top as its original block reaches the viewport edge. The pinned block takes over before any prompt text is clipped, rather than waiting for the original to disappear. Scrolling through older turns selects their corresponding prompts, including repeated prompt text. The previous pin yields when the next user block reaches its space, keeping that next block unobscured.

The pinned block starts on the first viewport row and aligns with the original prompt's left edge. It reuses the transcript's rendered lines, displays at most three lines, and marks longer prompts with an ellipsis. Any remaining visible tail of the original block is hidden while its compact copy is pinned. A clickable `▲` is centered in the separator row below the prompt; clicking it scrolls the complete original user block to the top of the viewport. The pinned header occupies at most half the transcript viewport and is hidden in very short viewports, while dialogs are open, and during text selection. Regular terminal mode uses terminal-owned scrollback and does not support pinning.

The implementation hooks the fullscreen compositor before overlays and reads the current frame's layout and cached container child heights. The arrow has its own one-cell hit region in that frame and uses Pi's normalized mouse events. These are internal Pi interfaces, isolated in `packages/user-message/src/sticky-prompt.ts`; changing Pi versions requires checking them against the runtime. It neither rerenders the transcript to measure it nor registers an overlay, so scrolling, scrollbar dragging, and editor focus retain their normal behavior. Session shutdown and widget disposal release the hook and click target.
